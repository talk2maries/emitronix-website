# Emitronix data-layer specification

Version: 1.0
Owner: Emitronix website backend
Browser implementation: `lib/gtm/dataLayer.ts`

## Rules

- `lead_id` is generated by the server ledger and returned only after Zoho completes the create/update operation.
- `event_id` equals `lead_id`; the client suppresses the event if the current field and legacy API alias ever disagree.
- `submission_id` is the browser transport idempotency UUID. It is not the conversion transaction ID.
- The Zoho CRM record ID remains server-side. The browser receives only the internal ledger `lead_id` needed for conversion reconciliation.
- Raw `gclid`, `gbraid` and `wbraid` values never enter `dataLayer`; only availability booleans do.
- Page URLs and referrers are reduced to origin plus pathname. Query strings and fragments are removed.
- Campaign/ad-group IDs, keyword and free-text UTM values are omitted from browser events; they remain in the consent-gated backend attribution record.
- Customer name, email, phone, company, message, location and form-field values are prohibited.
- Tag-specific consent checks remain mandatory in GTM even when the website suppresses an event.

## `generate_lead`

Fires once after the server confirms Zoho success. It does not fire for validation errors, API errors, network errors, honeypot responses, in-progress requests or replayed submissions.

```js
window.dataLayer.push({
  event: "generate_lead",
  event_id: "SERVER_LEAD_ID",
  lead_id: "SERVER_LEAD_ID",
  submission_id: "TRANSPORT_UUID",
  form_name: "contact_form",
  lead_source: "google_ads",
  page_location: "https://emitronix.ae/contact",
  page_path: "/contact",
  page_referrer: "https://www.google.com/search",
  gclid_available: true,
  gbraid_available: false,
  wbraid_available: false,
  match_type: "e",
  device: "m",
  network: "g",
  lead_value: 250,
  currency: "AED"
});
```

`lead_value=250` follows the supplied Phase 2A example and remains a configurable proposed website-enquiry value. It is distinct from the backend `qualified_lead` conversion value, even if both are initially AED 250. The account administrator must approve the website-enquiry value before the Ads tag is published.

In GTM-MSM8MPD6, the Website Lead Google Ads tag must map its Transaction ID field to `{{DLV - lead_id}}`. Do not concatenate the form name, Zoho record ID, campaign, stage or timestamp. Backend Data Manager events for later CRM stages use this exact same ID in their own distinct conversion actions.

Campaign/ad-group IDs, keyword and free-text UTM fields are intentionally omitted from the browser event because URL parameters are visitor-controlled and can contain personal data. They remain in the consent-gated server/Zoho attribution record. Only click-ID availability booleans and tightly allowlisted Google enums are exposed to GTM.

## Form lifecycle

| Event | When | Fields | Conversion use |
| --- | --- | --- | --- |
| `form_start` | First focus in a tracked commercial form | `form_name`, safe page fields | GA4 diagnostic only |
| `form_submit` | Valid form immediately before API dispatch | `submission_id`, `form_name`, safe page fields | Never a conversion |
| `form_error` | Native validation, HTTP API failure or network failure | `submission_id`, `form_name`, `error_type`, optional numeric `http_status`, optional field name | Diagnostic only |
| `form_abandon` | Started, incomplete form at `pagehide` | `form_name`, safe page fields | Diagnostic only |
| `generate_lead` | Server-confirmed Zoho create/update | Lead contract above | Direct Ads website conversion and GA4 event |
| `crm_lead_created` | Same confirmed response | Lead IDs, `crm_action=created|updated`, safe attribution | Audit/GA4 only |

Tracked `form_name` values are `contact_form` and `blog_enquiry_form`. Career, search, cookie settings and administration forms are excluded.

## Contact clicks

| Event | Match rule | Data |
| --- | --- | --- |
| `phone_click` | `tel:` target exactly matches an approved Emitronix number | Public business `phone_number`, canonical `click_url`, `button_location`, safe page fields |
| `whatsapp_click` | `wa.me`, `api.whatsapp.com` or `web.whatsapp.com` target contains the approved business WhatsApp number | Public business `phone_number`, canonical `click_url`, `button_location`, safe page fields |
| `email_click` | `mailto:` target exactly matches the approved Emitronix address | Canonical business `click_url`, `button_location`, safe page fields |

WhatsApp share links without the approved number are excluded. Query text, email subjects/bodies, arbitrary click text and CSS classes are not forwarded.

## SalesIQ

- `salesiq_chat_start` fires once per browser session when the website successfully invokes the SalesIQ window API. It is secondary-only and requires Functional consent.
- `salesiq_lead_captured` is exposed as `window.EmitronixTracking.salesIqLeadCaptured({ leadId, captureType })`. Connect it only to a verified SalesIQ callback and pass the internal non-PII lead ID, never a Zoho record ID or visitor fields.
- Chat opening alone must not fire `generate_lead`.
- A SalesIQ-to-Zoho CRM lead should be confirmed through a server workflow before it is treated as a qualified or offline conversion.

## CRM lifecycle events

`qualified_lead`, `meeting_booked`, `quotation_submitted` and `deal_won` are defined by the Zoho/Data Manager backend. They are not emitted by browser JavaScript because the browser cannot authoritatively know CRM status or deal value. GTM variables/triggers for these names should remain absent or paused unless a secure server-to-browser transport is separately approved.

## Consent behavior

| Consent | Browser event behavior |
| --- | --- |
| Analytics only | Form diagnostics, route views and non-advertising `generate_lead`; advertising attribution is removed |
| Marketing only | Server-confirmed lead and approved contact-click events; form diagnostics remain suppressed |
| Functional only | SalesIQ UI and its safe custom events |
| None | No custom measurement events |

GTM tags must additionally require `analytics_storage`, `ad_storage`, `ad_user_data` and/or Functional consent as appropriate.
