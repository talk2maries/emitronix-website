### Arabic on-page implementation notes

- Prefer natural Modern Standard Arabic. Do not repeat the exact primary query more than needed; use synonyms such as **مقاول**، **شركة مقاولات**، **أعمال بناء** and **تنفيذ** by context.
- Keep Latin acronyms in uppercase (`DEWA`, `DDA`, `DCD`, `RTA`, `DIFC`, `DMCC`, `DIP`, `JAFZA`) and explain the Arabic authority name on first use.
- Use `dir="rtl"` and Arabic punctuation; preserve phone numbers, URLs and acronyms in isolated LTR spans where the component already supports this.
- An image alt should describe what is visually present. “مولدة بالذكاء الاصطناعي” and “ليست صورة مشروع” are appropriate where the current asset is illustrative; do not force target keywords into decorative image alts.
- Do not add `FAQPage` markup unless the same questions and answers are visible to users on the rendered page.

## Hreflang, internal-link and Arabic query controls

- Every Arabic canonical should point to its own absolute `/ar...` URL, with reciprocal `ar-AE`, `en-AE` and `x-default` alternates matching the English counterpart.
- Link each Arabic blog article to the matching Arabic service using descriptive anchors: **خدمات المقاولات المدنية** → `/ar/civil`, **إنشاء المستودعات في دبي** → `/ar/warehouse-construction`, and **خدمات موافقات دبي** → `/ar/approval`.
- Link service pages to the precise authority page only where the visible section explains the relationship; for example, warehouse fire-safety content → **موافقات الدفاع المدني** and utility content → **موافقات DEWA**.
- Link every core service and authority page to `/ar/contact` with varied, natural CTA anchors such as **ناقش نطاق مشروعك** or **اطلب مراجعة متطلبات المشروع**, not repeated exact-match keywords.
- Use the Arabic service page as the canonical Arabic target even when users search in English acronyms. Do not create separate `/ar/dewa-approval-dubai` or other duplicate aliases merely for spelling variants.
- For future location pages, publish one substantial location hub per meaningful area, with unique jurisdiction, access, asset-type and planning guidance. Avoid service-by-location doorway-page multiplication.
